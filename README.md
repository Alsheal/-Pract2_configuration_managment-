# Визуализатор графа зависимостей

## Описание проекта

**Визуализатор графа зависимостей** — учебное приложение на Python для анализа зависимостей программных пакетов, построения ориентированного графа и его визуализации в форматах SVG и Mermaid.

Проект разработан в рамках дисциплины «Конфигурационное управление». Вариант № 26.

Приложение поддерживает два режима работы:

- **Тестовый режим** — загрузка пакетов и зависимостей из локального YAML-файла.
- **Режим Cargo** — получение информации о пакетах из индекса crates.io без использования Cargo для анализа зависимостей внутри приложения.

Результатом работы является граф зависимостей, содержащий названия пакетов, их версии и связи между ними. Программа также выводит порядок загрузки зависимостей.

## Цель проекта

Разработать приложение, позволяющее:

- получать информацию о выбранном программном пакете;
- определять его прямые и транзитивные зависимости;
- строить ориентированный граф зависимостей;
- ограничивать глубину анализа;
- обрабатывать циклические зависимости;
- определять порядок загрузки пакетов;
- создавать SVG- и Mermaid-представления графа.

- настройка имени выходного SVG-файла;

- обработка ошибок конфигурации;

### Этап 2. Загрузка репозитория и получение зависимостей

**Статус: завершён.**

Реализованы:

- загрузка данных из YAML-файла тестового репозитория;
- получение метаданных пакетов из индекса crates.io;
- выбор требуемой версии пакета;
- извлечение прямых зависимостей;

- исключение необязательных зависимостей, для которых не реализована активация через Cargo features.

### Этап 3. Построение графа зависимостей

**Статус: завершён.**

Реализованы:

- представление пакетов в виде вершин ориентированного графа;

- хранение имени, версии и глубины каждой вершины;
- построение графа с использованием итеративного обхода в глубину (DFS), без рекурсивных вызовов;
- ограничение максимальной глубины анализа;
- исключение повторяющихся вершин и рёбер;
- обработка циклических зависимостей;
- обработка отсутствующих пакетов;
- формирование структуры графа для последующей визуализации.

### Этап 4. Определение порядка загрузки и сравнение с Cargo

**Статус: реализован.**

Реализованы:

- определение порядка загрузки пакетов на основе построенного графа;
- вывод порядка загрузки в консоль;
- проверка результатов на реальных пакетах;
- сравнение полученного графа с выводом штатного инструмента Cargo (`cargo tree`);

### Этап 5. Визуализация графа и комплексное тестирование

**Статус: реализован.**

Реализованы:

- проверка корректности структуры графа перед визуализацией;
- размещение вершин с учётом глубины зависимостей;
- отображение пакетов, версий и глубины;

- экранирование специальных XML-символов;
- сохранение SVG-файла;
- формирование текстового представления графа в формате Mermaid;
- сохранение Mermaid-файла с расширением `.mmd`;
- создание родительского каталога при необходимости;
- обработка ошибок при формировании файлов;
- автоматическое тестирование основных компонентов;
- демонстрация работы на трёх пакетах: `serde_json`, `tokio` и `clap`.

### Назначение основных модулей

- `main.py` — точка входа, обработка аргументов командной строки и последовательный запуск этапов приложения.
- `config.py` — загрузка и проверка конфигурации.
- `repository.py` — загрузка тестового репозитория и получение метаданных Cargo.
- `analyzer.py` — анализ прямых и транзитивных зависимостей.
- `graph.py` — построение ориентированного графа и определение порядка загрузки пакетов.
- `renderer.py` — создание SVG- и Mermaid-представлений графа.

Каталог `tests/` содержит автоматические тесты отдельных модулей. В `tests/fixtures/` расположены тестовые данные репозитория.

## Конфигурация приложения

Настройки приложения хранятся в файле `config.yaml`.

Пример конфигурации для работы с Cargo:

```yaml
package_name: serde_json
repository: https://crates.io
test_repository_mode: false
version: "1.0.0"
output_file: serde-json-dependencies.svg
max_depth: 2
```

Пример конфигурации для тестового режима:

```yaml
package_name: PACKAGE
repository: tests/fixtures/repository.yaml
test_repository_mode: true
version: "1.0.0"
output_file: dependencies.svg
max_depth: 3
```

В тестовом режиме имя пакета должно соответствовать имени пакета в тестовом репозитории и требованиям его формата.

### Описание параметров

| Параметр | Тип | Назначение |
|---|---|---|
| `package_name` | Строка | Имя анализируемого пакета |
| `repository` | Строка | URL репозитория или путь к YAML-файлу |
| `test_repository_mode` | Логическое значение | Выбор тестового режима |
| `version` | Строка | Версия анализируемого пакета |
| `output_file` | Строка | Имя выходного SVG-файла |
| `max_depth` | Целое число | Максимальная глубина анализа |

При сохранении визуализаций программа формирует SVG-файл с указанным именем и соответствующий Mermaid-файл с расширением `.mmd`.

## Установка и запуск

### 1. Переход в каталог проекта

```bash
cd dependency-visualizer
```

### 2. Создание виртуального окружения

```bash
python3 -m venv .venv
```

Если виртуальное окружение уже создано, повторять команду не требуется.

### 3. Активация виртуального окружения

```bash
source .venv/bin/activate
```

### 4. Установка зависимостей

```bash
python -m pip install -r requirements.txt
```

### 5. Настройка пути к исходному коду

```bash
export PYTHONPATH="$PWD/src"
```

### 6. Настройка конфигурации

Откройте `config.yaml` и укажите параметры анализируемого пакета.

### 7. Запуск приложения

```bash
python -m dependency_visualizer.main
```

Можно явно указать конфигурационный файл:

```bash
python -m dependency_visualizer.main --config config.yaml
```

Также поддерживается короткая форма:

```bash
python -m dependency_visualizer.main -c config.yaml
```

После запуска приложение:

1. Загружает и проверяет конфигурацию.
2. Получает данные репозитория.
3. Определяет прямые и транзитивные зависимости.
4. Строит ориентированный граф.
5. Определяет порядок загрузки пакетов.
6. Создаёт SVG- и Mermaid-файлы.

## Сравнение с Cargo

Для проверки результатов использовался штатный инструмент:

```bash
cargo tree
```

Сравнение выполнялось на одинаковых версиях анализируемых пакетов.

В ходе проверки установлено:

- для `serde_json@1.0.0` состав графа совпал на проверенной глубине;
- для `tokio@1.40.0` после исключения зависимостей с непустым `target` состав графа совпал на проверенной глубине;
- для `clap@4.5.0` обнаружено отличие, связанное с необязательными зависимостями, активируемыми через Cargo features.

### Ограничения реализации

Текущая версия является учебным визуализатором, а не полной заменой Cargo.

В частности:

- не реализовано полноценное разрешение Cargo features;
- необязательные зависимости не активируются в соответствии с выбранными функциями;
- зависимости с непустым `target` исключаются, а не анализируются для конкретной платформы;
- механизм разрешения версий упрощён по сравнению с Cargo.

Эти ограничения необходимо учитывать при сравнении результатов приложения со штатным инструментом Cargo.
