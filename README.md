# Визуализатор графа зависимостей

## Описание проекта

**Визуализатор графа зависимостей** — учебный проект на Python, предназначенный для анализа зависимостей программных пакетов, построения графа зависимостей и его визуализации в формате SVG.

Проект разрабатывается в рамках дисциплины «Конфигурационное управление». Вариант № 26.

Разработка разделена на пять этапов. На текущий момент реализованы и протестированы первый и второй этапы: загрузка и проверка конфигурации приложения, загрузка тестового репозитория и анализ зависимостей программных пакетов.

## Цель проекта

Разработать приложение, которое позволяет анализировать зависимости выбранного программного пакета, строить граф зависимостей и представлять результат в виде графического изображения.

## Этапы разработки

### Этап 1. Конфигурация и интерфейс командной строки

Реализованы следующие возможности:

- загрузка параметров из YAML-файла;
- проверка наличия обязательных параметров;
- проверка корректности значений конфигурации;
- проверка имени пакета;
- проверка версии пакета в формате SemVer;
- проверка режима работы с тестовым репозиторием;
- настройка имени выходного SVG-файла;
- настройка максимальной глубины анализа зависимостей;
- обработка ошибок конфигурации;
- запуск приложения через интерфейс командной строки;
- автоматические тесты для проверки конфигурации.

### Этап 2. Загрузка репозитория и анализ зависимостей

**Статус: завершён.**

Реализованы следующие возможности:

- загрузка данных о пакетах из YAML-файла тестового репозитория;
- проверка структуры и корректности данных репозитория;
- поиск выбранного пакета;
- получение информации о прямых зависимостях пакета;
- поиск транзитивных зависимостей;
- обход зависимостей с использованием алгоритма поиска в ширину (BFS);
- учёт заданной максимальной глубины анализа;
- обработка отсутствующих пакетов и некорректных данных;
- предотвращение повторного обхода пакетов при наличии циклических зависимостей;
- автоматические тесты загрузки репозитория и анализа зависимостей.

### Этап 3. Построение графа зависимостей

Планируемые задачи:

- представление пакетов в виде вершин графа;
- представление зависимостей в виде рёбер;
- построение графа на основе результатов анализа;
- обработка повторяющихся зависимостей;
- предотвращение бесконечного обхода циклических зависимостей;
- учёт максимальной глубины обхода;
- тестирование построения графа.

### Этап 4. Визуализация графа и формирование SVG

Планируемые задачи:

- визуальное представление вершин и рёбер графа;
- размещение элементов графа на изображении;
- формирование SVG-файла;
- сохранение результата по пути, указанному в конфигурации;
- обработка ошибок при создании выходного файла;
- проверка корректности сформированного SVG.

### Этап 5. Тестирование, документация и завершение проекта

**Статус: запланирован.**

Планируемые задачи:

- написание комплексных автоматических тестов;
- проверка корректности работы всех компонентов;
- проверка обработки ошибочных входных данных;
- проверка работы приложения на тестовом репозитории;
- обновление документации;
- проверка инструкций по установке и запуску;
- подготовка итоговой версии проекта.

### Описание основных файлов

- `src/dependency_visualizer/main.py` — точка входа в приложение, запуск и обработка параметров командной строки.
- `src/dependency_visualizer/config.py` — загрузка, проверка и обработка конфигурации.
- `src/dependency_visualizer/repository.py` — загрузка и проверка данных тестового репозитория.
- `src/dependency_visualizer/analyzer.py` — анализ прямых и транзитивных зависимостей пакетов.
- `src/dependency_visualizer/__init__.py` — файл инициализации Python-пакета.
- `config.yaml` — конфигурационный файл приложения.
- `requirements.txt` — список зависимостей Python.
- `tests/test_config.py` — автоматические тесты конфигурации.
- `tests/test_repository.py` — автоматические тесты загрузки и проверки репозитория.
- `tests/test_analyzer.py` — автоматические тесты анализа зависимостей.
- `tests/fixtures/repository.yaml` — тестовые данные репозитория.
- `.gitignore` — перечень файлов и каталогов, которые Git не должен отслеживать.

## Конфигурация приложения

Настройки приложения хранятся в файле `config.yaml`.

Пример конфигурации:

```yaml
package_name: serde
repository: tests/fixtures/repository.yaml
test_repository_mode: true
version: "1.0.0"
output_file: dependencies.svg
max_depth: 3
```

### Описание параметров

| Параметр | Тип | Описание |
|---|---|---|
| `package_name` | Строка | Имя анализируемого пакета |
| `repository` | Строка | Путь к репозиторию пакетов |
| `test_repository_mode` | Логическое значение | Включение режима работы с тестовым репозиторием |
| `version` | Строка | Версия пакета в формате SemVer |
| `output_file` | Строка | Имя выходного SVG-файла |
| `max_depth` | Целое число | Максимальная глубина анализа зависимостей |

## Установка и запуск

### 1. Создание виртуального окружения

```bash
python3 -m venv .venv
```

### 2. Активация виртуального окружения

```bash
source .venv/bin/activate
```

### 3. Установка зависимостей

```bash
python3 -m pip install -r requirements.txt
```

### 4. Запуск приложения

В корневом каталоге проекта выполните:

```bash
export PYTHONPATH="$PWD/src"
python -m dependency_visualizer.main
```

При необходимости можно явно указать конфигурационный файл:

```bash
python -m dependency_visualizer.main --config config.yaml
```

Для демонстрации второго этапа используется тестовый репозиторий `tests/fixtures/repository.yaml`.


В файле указаны пакеты, их версии и списки зависимостей.

### 2. Проверка загрузки и валидации репозитория

```bash
python -m pytest tests/test_repository.py -v
```

Тесты проверяют загрузку данных, структуру репозитория и обработку ошибочных входных данных.

## Пример работы

### Этап 1

При запуске приложения с текущей конфигурацией ожидается следующий вывод:

```text
Параметры конфигурации:
package_name: serde
repository: tests/fixtures/repository.yaml
test_repository_mode: true
version: 1.0.0
output_file: dependencies.svg
max_depth: 3
Этап 1 завершён: конфигурация корректна.
```

На первом этапе приложение проверяет конфигурацию.

### Этап 2

На втором этапе приложение загружает данные тестового репозитория и анализирует зависимости выбранного пакета.

Например, если в тестовом репозитории пакет `serde` зависит от `syn` и `quote`, а пакет `syn` зависит от `unicode-ident`, анализ позволяет определить прямые зависимости `serde` и транзитивную зависимость `unicode-ident`.

Для демонстрации результата второго этапа можно выполнить тесты загрузки репозитория и анализа зависимостей:

```bash
python -m pytest tests/test_repository.py tests/test_analyzer.py -v
```

Построение графа зависимостей и создание SVG-файла относятся к последующим этапам разработки.
